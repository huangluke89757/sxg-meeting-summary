# 格式规格

规格从四份真实周会纪要交叉验证得出，母版 `assets/template_standard.docx` 已固化，生成时只替换文字。

## 页面

| 项 | 值 |
|---|---|
| 纸张 | A4，21 × 29.7 cm（11906 × 16838 twips） |
| 页边距 | 上/下 2.54 cm（1440），左/右 3.18 cm（1803） |
| 页眉页脚 | 不设置。四份样例均无页眉页脚，母版保持无引用状态 |
| 分节 | 单节，`sectPr` 必须是 body 最后一个子元素 |

## 已知陷阱

- **清空 body 会丢页面设置**：`sectPr` 是 body 最后一个子元素，删除尾部元素时极易连它一起删掉，结果 `sections` 变成 0，页边距和落款结构全丢。重建 body 必须显式跳过 `sectPr`，新元素用 `sectPr.addprevious()` 挂载。
- **一个段落常被拆成多个 run**：例如「9:00」会被拆成 5 个 run。替换文本必须按文档顺序写入全部 `w:t`，多余的清空，不能只改第一个。
- **空格会丢**：写入 `w:t` 后必须给 `xml:space="preserve"`，否则「主 持 人：」里的空格被吞。
- **探测页眉页脚会造假象**：python-docx 访问 `section.header` 会自动补出 `headerReference`，读到的引用不代表原文件有。判断样例有没有页眉页脚要看 `word/document.xml` 原始 XML。
